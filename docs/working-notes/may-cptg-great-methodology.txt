structuroing a .ts file for use in UI across nuxt4

If you're structuring a .ts file for reuse across a Nuxt 4 UI, the best approach depends on what the file contains (types, constants, configuration, composables, utilities, etc.).

A common project structure looks like this:

app/
├── components/
├── composables/
├── pages/
├── utils/
├── types/
├── constants/
└── services/


1. Shared Types

types/user.ts

export interface User {
  id: string
  name: string
  email: string
}

export interface UserProfile extends User {
  avatar?: string
}

Usage:

import type { User } from '~/types/user'

const user: User = {
  id: '1',
  name: 'John',
  email: 'john@example.com'
}

4. Utility Functions

utils/formatDate.ts

export function formatDate(date: string) {
  return new Intl.DateTimeFormat('en-US').format(
    new Date(date)
  )
}

Usage:

import { formatDate } from '~/utils/formatDate'
5. Composables for Reactive UI State

composables/useSidebar.ts

export const useSidebar = () => {
  const isOpen = useState('sidebar', () => false)

  const toggle = () => {
    isOpen.value = !isOpen.value
  }

  return {
    isOpen,
    toggle
  }
}

Usage:

const { isOpen, toggle } = useSidebar()
6. Feature-Based Organization (Recommended for Large Apps)

Instead of organizing by file type:

features/
├── users/
│   ├── types.ts
│   ├── constants.ts
│   ├── composables.ts
│   └── api.ts
├── billing/
└── settings/

Example:

// features/users/types.ts
export interface User {
  id: string
  name: string
}

// features/users/constants.ts
export const USER_ROLES = [
  'admin',
  'user'
] as const

This scales much better as the application grows.

For Nuxt 4 specifically, a good rule is:

types/ → interfaces, types, enums
constants/ or data/ → static UI configuration
utils/ → pure functions
composables/ → reactive state and logic
services/ → API access
features/ → group related code when the app becomes large

Navigation Generated Automatically
// composables/useNavigation.ts

import { pages } from "~/content/pages"

export const useNavigation = () => {
  return Object.values(pages)
    .filter(page => page.showInNavigation)
    .sort(
      (a, b) =>
        (a.navigationOrder ?? 999) -
        (b.navigationOrder ?? 999)
    )
}

Usage:

<script setup lang="ts">
const navigation = useNavigation()
</script>

<template>
  <nav>
    <NuxtLink
      v-for="item in navigation"
      :key="item.route"
      :to="item.route"
    >
      {{ item.title }}
    </NuxtLink>
  </nav>
</template>
Page SEO Generated Automatically
// composables/usePageSeo.ts

import { pages } from "~/content/pages"

export function usePageSeo(pageKey: keyof typeof pages) {
  const page = pages[pageKey]

  useSeoMeta({
    title: page.seo.title,
    description: page.seo.description,
    keywords: page.seo.keywords?.join(", ")
  })

  return page
}

Usage:

<script setup lang="ts">
const page = usePageSeo("about")
</script>
Page Component
<script setup lang="ts">
import { pages } from "~/content/pages"

const page = pages.about

    <p>
      {{ page.hero?.subheading }}
    </p>
  </section>
</template>
Enterprise-Style Structure

As the site grows, split the file:

content/
├── pages/
│   ├── home.ts
│   ├── about.ts
│   ├── pricing.ts
│   ├── dashboard.ts
│   └── index.ts
├── navigation.ts
├── seo.ts
└── page-types.ts

Example:

// content/pages/about.ts

import type { PageDefinition } from "../page-types"

export const aboutPage: PageDefinition = {
  slug: "about",
  route: "/about",

  title: "About Us",

  description:
    "Learn more about our company.",

  seo: {
    title: "About Us | My Company",
    description:
      "Learn about our mission and values."
  },

  hero: {
    heading: "Our Story",
    subheading:
      "Building products people love."
  }
}

Then aggregate:

// content/pages/index.ts

import { aboutPage } from "./about"
import { homePage } from "./home"
import { pricingPage } from "./pricing"

export const pages = {
  home: homePage,
  about: aboutPage,
  pricing: pricingPage
}

This pattern works especially well because navigation, breadcrumbs, page headers, SEO, sitemap generation, search indexing, and permissions all come from the same typed data source, preventing duplication across your Nuxt application.
