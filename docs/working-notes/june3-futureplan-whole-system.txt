export const useValues = () => {
  const values = ref([
    {
      title: "Real Adventure",

    },
    {
      title: "Safety First",
      icon: "mdi-lifebuoy",

    },

      title: "Great Memories",

4) Rules of thumb / Pro rules (important stuff)

These are the “don’t regret this later” guidelines.

Rule 1: Never mix layout + data logic

Bad:

API calls inside card components

Good:

Section fetches data → passes to cards
Rule 2: One icon system only

Stick to:

MDI (mdi-*) only

Mixing icon packs = visual inconsistency later

Rule 3: Limit values per grid (3–6 max)

Why:

3 = marketing clarity
6 = max cognitive load

6 = people stop reading

Rule 4: Every section should answer ONE question

Examples:

“Why choose us?”
“What is rafting like?”
“Is it safe?”

If it answers 2 questions → split it.

Rule 5: Design for scanning, not reading

Your rafting users:

mobile
outdoors
low attention mode

So:

short titles
1 sentence max
strong icons
high contrast
Rule 6: Treat icons as a language

Example your system already implies:

mdi-hiking → adventure
mdi-lifebuoy → safety
mdi-camera → memories
mdi-river → nature

👉 Don’t randomly assign icons
👉 They become a semantic system

Vercel-Specific Rules
Rule 1

Prefer:

useAsyncData()

for SSR content.

Not:

onMounted()

for primary page data.

Rule 2

Static where possible.

Dynamic where necessary.

Use route rules.

Example:

routeRules: {
  '/': { prerender: true },
  '/trips/**': { swr: 3600 }
}
Rule 3

Avoid unnecessary client-side state.

Most marketing content should be:

SSR rendered
Rule 4

Optimize for edge caching.

Content changes:

Rarely

Exploit that.

Nuxt 4 Rules of Thumb
Components

If a component exceeds:

200-300 lines

split it.

Composables

One responsibility only.

Bad:

useTripsAndBookingsAndWeather

Good:

useTrips
useBookings
useWeather
Props

Pass data down.

Avoid prop drilling deeper than 2 levels.

Use composables instead.

State

Ask:

Does this need global state?

Most of the time:

No.

Golden Rule

Build the architecture today as if you'll have:

50 trips
10 rivers
20 guides
5 years of content

But implement only what you need for:

3 trips
1 river
1 booking form

That balance is where Nuxt 4 + Vuetify 4 + Vercel really shines: simple now, scalable later.
